# XDU Campus Activities Platform 项目全景文档

> 面向高校场景的校园大型活动报名、审核、签到、通知与校园圈互动平台

---

## 一、项目定位

本项目聚焦校园大型活动管理全链路，覆盖活动发布、平台审核、报名审核、异步确认、签到核销、通知推送、校园圈互动、AI 审核建议与个性化推荐等能力。系统面向三类角色：普通用户、活动负责人、平台管理员，支持从活动创建到活动履约的完整业务闭环。

---

## 二、三类角色与核心功能

| 角色 | 核心能力 |
|---|---|
| **普通用户 (USER)** | 浏览活动、报名（审核制/先到先得）、查看报名状态与签到凭证、收藏活动、通知中心、校园圈发帖/点赞/评论、"为你推荐" |
| **活动负责人 (ACTIVITY_ADMIN)** | 创建/编辑活动、上传图片、管理报名名单、审核报名/退出申请、签到核销（展示码/凭证ID）、签到数据看板 |
| **平台管理员 (PLATFORM_ADMIN)** | 审核活动发布申请、审核负责人申请、查看 AI 审核建议与相似活动、下架活动、审核历史 |

**关键数据流**：

- **MySQL**：核心业务数据持久化
- **Redis**：登录态、活动缓存、报名状态缓存、签到聚合缓存、Lua 脚本原子扣减
- **RocketMQ**：报名异步确认、通知事件、AI 审核事件、搜索索引同步
- **Elasticsearch**：活动搜索、筛选、聚合与向量召回
- **WebSocket**：报名结果与通知的实时推送

## 五、核心业务流程

### 5.1 活动发布审核流程

```
活动负责人创建/编辑活动
            │
            ▼
      活动进入待审核
            │
            ▼
      平台管理员审核
            │
            ▼
      AI 审核建议辅助
            │
            ▼
         通过/驳回
            │
            ▼
    通知中心与页面状态同步
```

### 5.2 审核制报名流程

```
用户提交报名申请
          │
          ▼
负责人查看待审核请求
          │
          ▼
     审核通过/驳回
          │
          ▼
生成报名结果与签到凭证
          │
          ▼
通知中心/页面状态同步
```

### 5.3 先到先得报名流程（高并发核心链路）

```
用户发起报名
      │
      ▼
Redis + Lua 原子校验
      │
      ▼
冻结名额并返回待确认
      │
      ▼
RocketMQ 异步落库
      │
      ▼
生成报名记录与签到凭证
      │
      ▼
WebSocket 推送最终结果
```

### 5.4 签到核销流程

```
报名成功生成唯一凭证
          │
          ▼
负责人输入展示码/凭证ID
          │
          ▼
校验活动/时间窗口/凭证状态/幂等
          │
          ▼
      更新签到状态
          │
          ▼
记录核销人/时间/统计数据
```

### 5.5 AI 推荐流程

```
用户行为 + 偏好标签
          │
          ▼
      生成用户画像
          │
          ▼
活动内容写入 ES 与向量索引
          │
          ▼
   规则召回 + 向量召回
          │
          ▼
 输出推荐理由与排序结果
```

## 八、项目八大亮点

### 1. Spring Security + RBAC 权限体系

采用正式 RBAC 角色权限模型，区分 `USER`、`ACTIVITY_ADMIN`、`PLATFORM_ADMIN` 三类角色，并通过角色与权限缓存支撑页面显隐与接口鉴权。

### 2. 审核制 + 先到先得制双报名模式

活动支持两种报名方式：审核制活动由负责人审核通过后确认名额，先到先得活动走 Redis 冻结名额 + MQ 异步确认链路，兼顾灵活性与并发性能。

### 3. 状态模式管理报名/退出审批流

报名申请、报名成功、报名驳回、退出申请、退出通过等状态均围绕统一活动状态流转，保证普通用户、负责人和通知中心看到一致结果。

### 4. Redis + Lua + MQ + WebSocket 高峰报名链路

先到先得活动通过 Redis + Lua 做原子校验与冻结名额，再由 RocketMQ 异步落库，最后通过 WebSocket 把最终结果推送给前端，降低高峰期数据库压力。

### 5. AOP + 令牌桶限流与降级

对报名、搜索、热点活动详情、通知查询、审核列表等关键接口统一接入基于 AOP 的限流能力，并提供按场景拆分的降级策略。

### 6. 消息通知中心

系统支持活动审核、报名成功/失败、报名审核、退出审核、主办方申请审核、动态互动等通知落库，并通过 WebSocket 进行实时推送。

### 7. 校园圈点赞评论系统

项目内置校园圈动态流，支持关联活动发布动态、点赞/取消点赞、评论/删除评论与通知联动，增强活动后的社交互动能力。

### 8. AI 审核与智能推荐

引入 AI 审核建议、相似活动召回、活动向量索引与用户画像构建，为管理员审核与个性化推荐提供支撑。

## 十一、Redis Lua 脚本（先到先得报名原子校验）

核心逻辑位于 `src/main/resources/activity_register.lua`：

1. 校验活动元数据是否存在
2. 校验活动状态是否允许报名
3. 校验报名时间窗口
4. 校验用户是否已报名
5. 校验用户历史报名状态（排除 PENDING_CONFIRM / SUCCESS / CANCEL_PENDING）
6. 校验库存是否充足
7. 原子扣减库存 + 冻结名额 + 记录用户状态

## 十三、中间件配置说明

### MySQL

- 本机映射端口：`3307`
- 默认数据库：`campus`
- 首次启动自动执行 `src/main/resources/db/init` 下的初始化脚本

### Redis

- 本机映射端口：`6378`
- 用于登录态、活动缓存、状态缓存、签到看板缓存

### RocketMQ

- NameServer 地址：`rocketmq-namesrv:9876`
- Broker 广播地址：`rocketmq-broker`
- 宿主机调试时 Broker IP 默认使用 `127.0.0.1`

### Elasticsearch

- 默认地址：`http://elasticsearch:9200`
- 默认索引：`activity_index_dev`
- 用于活动搜索、分类聚合、向量召回
