## 一、双报名模式(审核制 + 先到先得)

### 功能概述

系统支持两种报名方式:
- **审核制**: 用户报名后需负责人审核,审核通过后确认名额
- **先到先得**: 用户报名后系统自动确认名额,支持高并发场景

### 代码实现位置

- 核心业务: [ActivityServiceImpl.java](src/main/java/com/campus/service/impl/ActivityServiceImpl.java)
- Redis Lua脚本: [activity_register.lua](src/main/resources/activity_register.lua)
- MQ消费者: [ActivityRegistrationConsumer.java](src/main/java/com/campus/mq/ActivityRegistrationConsumer.java)

### 技术实现方案

#### 1. 审核制报名

**流程**:
```
用户提交报名申请 → 负责人审核 → 审核通过/驳回 → 生成签到凭证 → 通知用户
```

**关键代码逻辑**:
- 用户提交报名后,状态设为`PENDING`(待审核)
- 负责人在`reviewRegistration`方法中审核报名
- 审核通过后更新状态为`SUCCESS`,生成签到凭证
- 审核驳回后更新状态为`REJECTED`,通知用户

#### 2. 先到先得报名(高并发核心链路)

**流程**:
```
用户发起报名 → Redis+Lua原子校验 → 冻结名额 → RocketMQ异步落库 → WebSocket推送结果
```

**Redis Lua脚本核心逻辑** (`activity_register.lua`):

```lua
-- 1. 校验活动元数据是否存在
if redis.call('exists', metaKey) == 0 then
    return 6
end

-- 2. 校验活动状态是否允许报名
local status = tonumber(redis.call('hget', metaKey, 'status') or '-1')
if status ~= 2 and status ~= 5 then
    return 3
end

-- 3. 校验报名时间窗口
local registrationStart = tonumber(redis.call('hget', metaKey, 'registrationStartEpoch') or '0')
if registrationStart > 0 and nowEpoch < registrationStart then
    return 4
end

-- 4. 校验用户是否已报名
if redis.call('sismember', usersKey, userId) == 1 then
    return 2
end

-- 5. 校验库存是否充足
local stock = tonumber(redis.call('get', stockKey) or '-1')
if stock <= 0 then
    return 1
end

-- 6. 原子扣减库存 + 冻结名额 + 记录用户状态
redis.call('incrby', stockKey, -1)
redis.call('incrby', frozenKey, 1)
redis.call('sadd', usersKey, userId)
redis.call('hmset', userStateKey,
    'status', 'PENDING_CONFIRM',
    'requestId', requestId,
    'message', '报名申请已提交，等待主办方审核'
)
```

**异步确认流程**:

```java
// ActivityRegistrationConsumer.java

    topic = "${campus.activity.register.topic}",
    consumerGroup = "${campus.activity.register.consumer-group}"
)
public class ActivityRegistrationConsumer implements RocketMQListener<ActivityRegistrationEventDTO> {
    @Override
    public void onMessage(ActivityRegistrationEventDTO message) {
```

### 为什么这样设计?

1. **原子性保证**: Redis Lua脚本确保库存扣减、用户状态记录等操作原子执行,避免超卖
2. **削峰填谷**: MQ异步落库降低数据库压力,应对高并发报名场景
3. **用户体验**: WebSocket实时推送报名结果,用户无需刷新页面
4. **灵活适配**: 两种模式满足不同场景需求,审核制适合名额有限的活动,先到先得适合大型活动

## 三、签到核销功能

### 功能概述

报名成功后生成唯一签到凭证,活动负责人通过展示码或凭证ID完成签到核销,记录核销人、时间和统计数据。

### 代码实现位置

- 核心业务: [ActivityServiceImpl.java](src/main/java/com/campus/service/impl/ActivityServiceImpl.java) - `verifyCheckIn`方法
- 签到记录: [ActivityCheckInRecord.java](src/main/java/com/campus/entity/ActivityCheckInRecord.java)
- 签到凭证: [ActivityVoucher.java](src/main/java/com/campus/entity/ActivityVoucher.java)

### 签到流程

```
报名成功生成唯一凭证 → 负责人输入展示码/凭证ID → 校验活动/时间窗口/凭证状态/幂等 → 更新签到状态 → 记录核销人/时间/统计数据
```

### 核心代码实现

```java
@Override
public Result verifyCheckIn(Long activityId, ActivityCheckInVerifyDTO dto, String idempotencyKey) {
    // 1. 权限校验
    Result authResult = requirePermission(RbacConstants.PERM_CHECKIN_VERIFY, "无权执行签到核销");
    if (authResult != null) {
        return authResult;
    }
    
    // 2. 活动校验
    Activity activity = getById(activityId);
    if (activity == null) {
        return Result.fail("活动不存在");
    }
    
    // 3. 操作人校验
    Long operatorId = UserHolder.getUser().getId();
    if (!Objects.equals(activity.getCreatorId(), operatorId)) {
        return Result.fail("仅活动创建者可核销签到");
    }
    
    // 4. 幂等性保证
    String redisKey = CACHE_CHECK_IN_KEY + activityId + ":" + dto.getVoucherId();
    String fingerprint = buildFingerprint(dto, operatorId);
    CachedCheckInResult cached = cacheClient.queryWithPassThrough(
        redisKey, fingerprint, CachedCheckInResult.class,
        key -> new CachedCheckInResult(null, null),
        CACHE_CHECK_IN_TTL, TimeUnit.MINUTES
    );
    
    if (cached.getResult() != null) {
        return cached.getResult();
    }
    
    // 5. 执行签到核销
    Result result = doVerifyCheckIn(activity, dto, operatorId, idempotencyKey, fingerprint);
    
    // 6. 缓存签到结果
    cacheCheckInResult(redisKey, fingerprint, result);
    return result;
}
```

```java
private RuleCheckResult runRuleCheck(Activity activity) {
    RuleCheckResult result = new RuleCheckResult();
    
    // 活动简介长度校验
    if (StrUtil.isBlank(activity.getSummary()) || StrUtil.length(StrUtil.trim(activity.getSummary())) < 12) {
        result.problems.add("活动简介较短，建议补充活动背景和目标");
    }
    
    // 活动详情长度校验
    if (StrUtil.isBlank(activity.getContent()) || StrUtil.length(StrUtil.trim(activity.getContent())) < 40) {
        result.problems.add("活动详情描述偏短，建议补充流程、参与方式和注意事项");
    }
    
    // 必填字段校验
    if (StrUtil.isBlank(activity.getOrganizerName())) {
        result.missingFields.add("主办方名称");
    }
    if (StrUtil.isBlank(activity.getContactInfo())) {
        result.missingFields.add("主办方联系方式");
    }
    
    // 时间逻辑校验
    if (activity.getRegistrationEndTime() != null && activity.getEventStartTime() != null
            && activity.getRegistrationEndTime().isAfter(activity.getEventStartTime())) {
        result.problems.add("报名截止时间晚于活动开始时间");
    }
    
    return result;
}
```

```java
private SimilarSearchResult searchSimilarActivities(Activity activity) {
    // 使用ES的multi_match查询召回相似活动
    BoolQueryBuilder query = QueryBuilders.boolQuery()
        .filter(QueryBuilders.termsQuery("status", List.of(STATUS_PUBLISHED, STATUS_OFFLINE_PENDING_REVIEW)))
        .mustNot(QueryBuilders.termQuery("_id", String.valueOf(activity.getId())));
    
    String keyword = StrUtil.blankToDefault(activity.getTitle(), 
        StrUtil.blankToDefault(activity.getSummary(), activity.getCategory()));
    
    if (StrUtil.isNotBlank(keyword)) {
        query.must(QueryBuilders.multiMatchQuery(keyword)
            .field("title", 4.0f)
            .field("category", 3.0f)
            .field("tags", 3.0f)
            .field("summary", 2.0f)
            .field("content", 1.0f)
            .type(MultiMatchQueryBuilder.Type.BEST_FIELDS));
    }
    
    // 返回前3个最相似的活动
    sourceBuilder.size(3);
}
```

```java
public Double calculate(RecommendationCandidate candidate) {
    double score = 0D;
    
    // 1. 标签匹配分数 (权重: 30%)
    score += candidate.getTagScore() * 0.30;
    
    // 2. 分类匹配分数 (权重: 20%)
    score += candidate.getCategoryScore() * 0.20;
    
    // 3. 热度分数 (权重: 15%)
    score += candidate.getHeatScore() * 0.15;
    
    // 4. 时间分数 (权重: 15%)
    score += candidate.getTimeScore() * 0.15;
    
    // 5. 互动分数 (权重: 10%)
    score += candidate.getInteractionScore() * 0.10;
    
    // 6. 向量相似度分数 (权重: 10%)
    if (candidate.getVectorMatched()) {
        score += candidate.getVectorScore() * 0.10;
    }
    
    return score;
}
```

```java
public String build(RecommendationCandidate candidate) {
    List<String> reasons = new ArrayList<>();
    
    // 1. 标签匹配理由
    if (!candidate.getMatchedTagNames().isEmpty()) {
        reasons.add("包含你感兴趣的标签: " + String.join("、", candidate.getMatchedTagNames()));
    }
    
    // 2. 分类匹配理由
    if (candidate.getMatchedPrimaryCategory()) {

    // 3. 热门理由

        reasons.add("热度最高的活动");
    }
    
    // 4. 即将开始理由
    if (candidate.getUpcomingSoon()) {
        reasons.add("即将开始,不要错过");
    }
    
    // 5. 向量相似理由
    if (candidate.getVectorMatched()) {
        reasons.add("与你参与过的活动相似");
    }
    
    return String.join("; ", reasons);
}
```

### 为什么这样设计?

1. **AI辅助审核**: 减轻管理员审核负担,提供客观参考建议
2. **规则+向量混合召回**: 兼顾精准性和多样性,提升推荐效果
3. **多维度评分**: 综合考虑标签、分类、热度、时间等因素,推荐更合理
4. **推荐理由可解释**: 为每个推荐结果生成理由,提升用户信任度
5. **缓存优化**: 推荐结果缓存,减少计算开销

## 七、AOP限流与降级

### 功能概述

对报名、搜索、热点活动详情、通知查询、审核列表等关键接口统一接入基于AOP的限流能力,并提供按场景拆分的降级策略。

### 代码实现位置

### 限流配置

| 场景 | 容量 | 补充速率(token/s) | 降级策略 |
|---|---|---|---|
| 报名 (register) | 80 | 40 | 直接失败 (FAIL) |
| 搜索 (search) | 50 | 25 | 简化搜索 (SEARCH_SIMPLIFIED) |
| 热点活动详情 (activity-detail-hot) | 80 | 40 | 返回缓存 (ACTIVITY_DETAIL_CACHE) |
| 审核列表 (review-list) | 10 | 5 | 直接失败 (FAIL) |
| 通知列表 (notification-list) | 20 | 10 | 直接失败 (FAIL) |
| 未读数 (notification-unread) | 20 | 10 | 直接失败 (FAIL) |

#### 限流注解

#### 限流切面

```java
@Aspect
@Component
public class RateLimitAspect {
    private final RateLimitManager rateLimitManager;
    private final RateLimitFallbackService fallbackService;
    
    @Around("@annotation(rateLimit)")
    public Object around(ProceedingJoinPoint joinPoint, RateLimit rateLimit) throws Throwable {
        // 1. 获取限流规则
        RateLimitRule rule = rateLimitManager.getRule(rateLimit.scene());
        
        // 2. 判断是否需要限流
        if (rule == null || !rule.isEnabled() || !fallbackService.shouldApplyRateLimit(rateLimit.scene(), joinPoint.getArgs())) {
            return joinPoint.proceed();
        }
        
        // 3. 尝试获取令牌
        if (rateLimitManager.tryAcquire(rateLimit.scene(), rule)) {
            return joinPoint.proceed();
        }
        
        // 4. 触发限流,执行降级逻辑
        if (Result.class.isAssignableFrom(((MethodSignature) joinPoint.getSignature()).getReturnType())) {
            return fallbackService.handle(rateLimit.scene(), rule, joinPoint.getArgs());
        }
        
        throw new IllegalStateException("Rate limit fallback only supports Result return type");
    }
}
```

#### 令牌桶算法

```java
public class TokenBucketLimiter {
    private final long capacity;
    private final long refillRate;
    private final AtomicInteger tokens;
    private final AtomicLong lastRefillTimestamp;
    
    public boolean tryAcquire() {
        refill();
        return tokens.getAndDecrement() > 0;
    }
    
    private void refill() {
        long now = System.currentTimeMillis();
        long elapsed = now - lastRefillTimestamp.get();
        if (elapsed > 0) {
            long newTokens = (elapsed * refillRate) / 1000;
            if (newTokens > 0) {
                tokens.updateAndGet(current -> Math.min(capacity, current + newTokens));
                lastRefillTimestamp.set(now);
            }
        }
    }
}
```

#### 降级策略

```java
@Service
public class RateLimitFallbackService {
    public Result handle(String scene, RateLimitRule rule, Object[] args) {
        switch (rule.getFallbackMode()) {
            case FAIL:
                return Result.fail("系统繁忙，请稍后再试");
            
            case SEARCH_SIMPLIFIED:
                return handleSearchSimplified(args);
            
            case ACTIVITY_DETAIL_CACHE:
                return handleActivityDetailCache(args);
            
            default:
                return Result.fail("系统繁忙，请稍后再试");
        }
    }

        // 简化搜索逻辑,只查询基础字段,不进行复杂聚合
        return activitySearchService.searchSimplified(args);
    }

        // 直接返回缓存的活动详情,不查询数据库
        Long activityId = (Long) args[0];
        return cacheClient.queryWithPassThrough(
            CACHE_ACTIVITY_DETAIL_KEY,
            activityId,
            Activity.class,
            this::queryActivityById,
            CACHE_ACTIVITY_DETAIL_TTL,
            TimeUnit.MINUTES
        );
    }
}
```

## 八、状态模式管理报名/退出审批流

### 功能概述

报名申请、报名成功、报名驳回、退出申请、退出通过等状态均围绕统一活动状态流转,保证普通用户、负责人和通知中心看到一致结果。

### 状态定义

```java
// 报名状态
public static final int REGISTRATION_PENDING = 0;         // 待审核
public static final int REGISTRATION_SUCCESS = 1;         // 报名成功
public static final int REGISTRATION_REJECTED = 2;        // 报名驳回
public static final int REGISTRATION_CANCELLED = 3;       // 已取消
public static final int REGISTRATION_CANCEL_PENDING = 4;  // 退出申请中
```

### 状态流转逻辑

```
用户报名 → PENDING(待审核)
         ↓
负责人审核 → SUCCESS(报名成功) / REJECTED(报名驳回)
         ↓
用户退出 → CANCEL_PENDING(退出申请中)
         ↓
负责人审核 → CANCELLED(已取消) / SUCCESS(维持原状)
```

### 核心代码实现

#### 报名审核

```java
@Override
@Transactional
public Result reviewRegistration(Long activityId, Long registrationId, ReviewActionDTO dto) {
    // 1. 校验活动和报名记录
    Activity activity = getById(activityId);
    ActivityRegistration registration = activityRegistrationMapper.selectById(registrationId);
    
    if (!Objects.equals(registration.getStatus(), REGISTRATION_PENDING)) {
        return Result.fail("只能审核待审核的报名");
    }
    
    // 2. 审核通过
    if (Boolean.TRUE.equals(dto.getApproved())) {
        registration.setStatus(REGISTRATION_SUCCESS);
        registration.setReviewedAt(LocalDateTime.now());
        activityRegistrationMapper.updateById(registration);
        
        // 生成签到凭证
        createVoucher(activityId, registration.getUserId());
        
        // 发送通知
        notifyRegistrationApproved(registration);
    } 
    // 3. 审核驳回
    else {
        registration.setStatus(REGISTRATION_REJECTED);
        registration.setReviewedAt(LocalDateTime.now());
        registration.setReviewRemark(dto.getRemark());
        activityRegistrationMapper.updateById(registration);
        
        // 发送通知
        notifyRegistrationRejected(registration, dto.getRemark());
    }
    
    return Result.ok();
}
```

#### 退出审核

```java
@Override
@Transactional
public Result reviewCancelRegistration(Long activityId, Long registrationId, ReviewActionDTO dto) {
    ActivityRegistration registration = activityRegistrationMapper.selectById(registrationId);
    
    if (!Objects.equals(registration.getStatus(), REGISTRATION_CANCEL_PENDING)) {
        return Result.fail("只能审核退出申请中的报名");
    }
    
    // 审核通过退出
    if (Boolean.TRUE.equals(dto.getApproved())) {
        registration.setStatus(REGISTRATION_CANCELLED);
        registration.setCancelledAt(LocalDateTime.now());
        activityRegistrationMapper.updateById(registration);
        
        // 释放名额
        releaseQuota(activityId);
        
        // 发送通知
        notifyCancelApproved(registration);
    } 
    // 驳回退出申请
    else {
        registration.setStatus(REGISTRATION_SUCCESS);
        activityRegistrationMapper.updateById(registration);
        
        // 发送通知
        notifyCancelRejected(registration, dto.getRemark());
    }
    
    return Result.ok();
}
```

### 为什么这样设计?

1. **状态机模式**: 明确的状态定义和流转规则,避免状态混乱
2. **一致性保证**: 状态变更、名额管理、通知发送统一在事务中处理
3. **可追溯性**: 记录审核时间、审核人、审核意见,支持审计
4. **通知联动**: 状态变更自动触发通知,用户及时了解进展
